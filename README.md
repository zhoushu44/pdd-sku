# 电商数据分析仪表板

[![Docker](https://img.shields.io/badge/docker-1.5-blue)](https://hub.docker.com)
[![React](https://img.shields.io/badge/react-18-blue)](https://react.dev)

🚀 **一站式电商运营数据分析平台** - 为拼多多商家打造的智能决策工具

支持销售分析、利润计算、营销评估、退款分析、智能建议，以及 **🆕 一键 AI SKU 生成与优化**。

---

## ✨ 核心特性

### 📊 数据总览
- **经营健康度评分** - 基于销售额、利润率、退款率、ROI 综合评估（绿/黄/红三档）
- **7 大核心指标** - 销售额、订单数、销量、客单价、营销花费、净利润、利润率
- **环比对比** - 今日 vs 昨日 / 7 天 vs 上 7 天 / 15 天 vs 上 15 天 / 30 天 vs 上 30 天
- **销售趋势图** - 日/周维度切换，含 SKU 维度趋势分析
- **热销榜单** - TOP 10 热销 SKU 排行榜
- **利润预警** - 低利润 SKU 实时提醒
- **涨价模拟器** - 模拟涨价 X% 查看利润变化
- **SKU 分类看板** - 爆品 / 风险品 / 衰退品智能分类

### 📦 商品分析
- 按规格维度的销售/成本/利润明细表
- 真实退款率自动计算（基于订单数据，按金额占比）
- 多列排序、搜索筛选
- 合计行自动汇总
- 退款率颜色分级（≥40% 红 / ≥20% 橙 / ≥10% 黄）

### 💰 成本与利润计算
- **XLSX 批量导入** - 按规格批量导入原材料成本、人工成本、运营成本等
- **XLSX 导出** - 含成本利润明细、利润分析数据、计算公式三个工作表
- **逐规格配置** - 原材料成本、人工成本、运营成本、快递费、包装耗材、运费险、商家承担优惠
- **退款率灵活设置** - 自动回用真实退款率或手动覆盖（假设分析）
- **退货损失计算** = 退款收入损失 + 退回运费损失
- **保本投产比** - 含退款损失的精确计算
- **定价建议** - 基于目标利润率反推售价
- **实时预览** - 单件净利润即时显示
- **自动保存** - 配置修改后自动保存到 localStorage

### 📈 营销数据分析
- 推广总览：花费、交易额、ROI、点击率、询单/收藏/关注指标
- 按商品维度的推广效果汇总
- 推广预算优化建议（基于净 ROI 给出加预算/维持/减预算/暂停建议）
- 利润影响模拟分析

### ↩️ 退款专项分析
- 退款总览：退款率、退款损失额、高退款率 SKU 数
- 高退款率 SKU 预警（退款率 > 20% 且订单数 ≥ 3）
- 退款明细表（支持搜索和排序）
- 退款率颜色分级显示

### 💡 智能运营建议中心
- **7 类智能建议**：
  - 🔴 亏损 SKU（净利润 < 0）
  - 🟠 低利润高销量（销量高于均值但利润率 < 5%）
  - 🔴 高退款率 SKU（退款率 > 20%）
  - 🔴 低 ROI 推广（净 ROI < 1）
  - 🟠 销售额环比下滑（降幅 > 10%）
  - 🔵 客单价环比下降（降幅 > 10%）
  - 🟢 利润健康提示（利润率 ≥ 15%）
- 按严重程度排序（critical / warning / info / success）
- 分类标签筛选

## 🆕 一键 AI SKU 工作台

> 基于 OpenAI 兼容大模型，输入商品描述即可自动生成完整 SKU 方案

### AI 价格 - 快速生成 SKU

输入商品描述（成本、运费、包装、人工、利润率要求），AI 自动生成完整 SKU 定价方案。

**支持模式：**
- ✅ 简单模式 - 快速生成基础 SKU
- ✅ 目标定价模式 - 指定各规格售价
- ✅ 自动推荐规格 - AI 根据商品特性推荐数量梯度（如 1 件/3 件/6 件/12 件装）

**生成内容：**
- 规格、商品名称、类型（标准款/引流款/利润款等）
- 成本单价、快递费、包装耗材、人工成本
- 定价、利润率、建议理由

### AI 分析 - 深度优化方案

输入商品描述 + 当前 SKU + 同行参考数据，AI 生成深度优化方案。

**优化维度：**
- 🎯 **低价引流款** - 生成具有价格竞争力的引流 SKU
- 💎 **利润款** - 优化现有 SKU 的利润率
- 📏 **规格扩展** - 建议增加新的规格（如大容量、多件装）
- 🎁 **套餐组合** - 生成混合捆绑套餐及套餐价格
- 📦 **库存策略款** - 针对销量集中度的优化建议
- 🏪 **同行对比分析** - 基于竞品价格生成更有竞争力的方案

### OpenAI 兼容模型配置

- ✅ 自定义 API 地址（第三方代理、私有化部署）
- ✅ 自定义 API Key
- ✅ 自定义模型名称（如 `gpt-4o-mini`、`gpt-5.4-mini` 等）
- ✅ 一键测试连接
- ✅ 配置持久化保存（localStorage）

### 可编辑的生成结果

- ✅ 生成后可逐行修改：SKU 名称、规格、成本、运费、人工、定价、利润率
- ✅ 勾选需要应用的 SKU
- ✅ 一键应用到当前表格并保存

### 示例引导

- ✅ 输入框内置清晰示例文本
- ✅ 支持简单列表和表格粘贴两种同行数据格式
- ✅ 💡 提示语引导用户正确输入

## ❓ 常见问题

**Q: 上传 CSV 后没有数据？**  
A: 检查 CSV 是否为拼多多标准导出格式，字段名需包含"商品规格"、"商家实收金额"、"售后状态"等。

**Q: 利润计算中退款率显示"真实 X%"？**  
A: 表示未启用手动退款率，系统自动使用订单数据计算的真实退款率。如需手动调整，请在配置弹窗中勾选"启用退款率"。

**Q: 保本投产比显示"无法保本"？**  
A: 表示单件净利润 ≤ 0（定价不足以覆盖成本 + 退款损失），需要提高定价或降低成本。

**Q: 配置丢失了？**  
A: 成本配置修改后会自动保存到浏览器 localStorage 中，清除浏览器数据或更换浏览器/设备会导致丢失。同一浏览器同一域名下持久保存。也可通过"导出结果 XLSX"导出配置，之后用"导入 XLSX"恢复。

**Q: 营销数据 Tab 没有内容？**  
A: 需要先上传营销推广数据（Excel/CSV），且数据时间范围与销售订单有重叠。

**Q: AI 功能无法连接？**  
A: 检查：1) API Key 是否正确 2) 网络是否正常 3) 模型名称是否正确。开发环境已配置代理，生产环境 Nginx 会自动处理 CORS。

### 方式二：传统 Docker 镜像

镜像基于多阶段构建（`node:20-alpine` 构建 + `nginx:1.27-alpine` 运行），容器内 nginx 监听 **80** 端口。

#### 宝塔 Docker 面板部署（推荐）

1. 在宝塔面板 **Docker → 镜像 → 拉取镜像**，输入 `<用户名>/trae-project:7.0` 或 `<用户名>/trae-project:latest`
2. **Docker → 容器 → 创建容器**，选择刚拉取的镜像
3. 端口映射设置为 `5173:5173`（或自定义端口）
4. **启动命令（Command）和入口点（Entrypoint）必须留空**，让容器使用镜像内置的默认启动命令
5. 勾选"自动重启"策略
6. 创建容器即可访问

> **重要**：不要在宝塔的"启动命令"字段中填写 `nginx -g daemon off;`，这会导致 `off;` 被错误拆分为独立参数，使 Nginx 启动失败并不断重启。正确做法是**清空启动命令字段**。

#### 命令行部署

```bash
# 拉取镜像（使用 7.0 版本）
docker pull <用户名>/trae-project:7.0

# 或使用最新版本
docker pull <用户名>/trae-project:latest

# 启动容器（宿主机 5173 → 容器 5173）
docker run -d \
  --name trae-project \
  --restart unless-stopped \
  -p 5173:5173 \
  --memory=512m \
  --cpus=1 \
  <用户名>/trae-project:7.0
```

访问 `http://localhost:5173` 即可。

#### 本地构建镜像

```bash
# 构建镜像
docker build -t trae-project .

# 启动容器
docker run -d -p 5173:5173 --name trae-project trae-project
```

访问 `http://localhost:5173` 即可。### 更新部署

### 部署排查清单

容器启动后无法访问时，按顺序检查：

1. **容器状态**：`docker ps` 确认容器在运行；若不断重启，检查 `docker logs` 是否出现 `nginx: invalid option: "off;"` — 这说明启动命令被错误覆盖，需清空 Command 字段
2. **端口映射**：`docker port <容器名>` 确认 `0.0.0.0:5173->5173/tcp` 存在
3. **本地访问**：在服务器上执行 `curl http://localhost:5173/` 验证容器内服务正常
4. **安全组**：云服务器控制台安全组规则放行对应端口入站（TCP）
5. **防火墙**：服务器系统防火墙放行（`firewall-cmd --add-port=5173/tcp --permanent && firewall-cmd --reload`）

### 端口说明

| 项 | 端口 | 说明 |
|----|------|------|
| 容器内 nginx | 5173 | 由 `nginx.conf` 中 `listen 5173` 决定 |
| Dockerfile EXPOSE | 5173 | 仅作声明，实际访问由 `-p` 映射决定 |
| 宿主机访问 | 自定义 | 通过 `-p 宿主机端口:5173` 映射 |
| Docker Compose | 5173 | 默认映射 `5173:5173`，可修改 `docker-compose.yml` |

## 📐 核心公式

### 利润计算

```
净利润 = 销售额 - 总成本 - 预估退款损失 - 引流成本总额

总成本 = 商品成本 + 人工成本 + 运营成本 + 平台技术服务费 (0.6%) + 快递费 + 包装耗材 + 运费险 + 商家承担优惠
（所有成本项均为单件费用 × 销量）

预估退款损失 = 退款收入损失 + 退回运费损失
  退款收入损失 = 销售额 × 退款率
  退回运费损失 = 销量 × 退款率 × 单件快递费

退款率优先级：用户手动启用 → 用户值；否则 → 真实退款率（自动回用）
真实退款率 = 退款成功额 / (有效销售额 + 退款成功额) × 100
```

### 保本投产比

```
保本投产 = 定价 / 单件净利润
单件净利润 = 定价 - 单件总成本 - 平台技术服务费 - 单件退回运费损失
```

### 定价建议

```
建议售价 = (固定成本 + 退回运费损失) / (1 - 平台扣点率 - 退款率 - 目标利润率)

固定成本 = 原材料成本 + 人工成本 + 运营成本 + 商家优惠 + 快递费 + 包装耗材 + 运费险
退回运费损失 = 单件快递费 × 退款率
平台扣点率 = 0.6%
```
